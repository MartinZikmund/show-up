# Show Up — Plan 5: Finish line (celebrations, statistics, brand and hero art, accessibility, store listing) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Everything the spec's milestone 11 still owes before a first store release: finishing a week, phase or program is celebrated (and a program can finally *be* finished), Pro gets real statistics, the app has its own icon, splash and hero art, the accessibility pass is done, and the store listing exists.

**Architecture:** All new logic is pure Core (`MilestoneDetector`, `StatsCalculator`, `CalendarFocusMap`) fed by the existing tracking services, so it is unit-tested without a head. The celebration rides the existing cross moment (`ICrossMoment`) instead of adding a second overlay. Statistics is a page under History, not a sixth tab. Charts are plain XAML shapes in `ItemsRepeater`s: no chart library, nothing new to trim or AOT. Art is generated by a script in `tools/` and committed as files; nothing is fetched at build time.

**Tech Stack:** Uno.Sdk 7.1 dev, CommunityToolkit.Mvvm, MSTest + AwesomeAssertions, XAML shapes and storyboards, SVG sources rasterized to WebP for hero art.

**Spec:** `docs/superpowers/specs/2026-11-21-show-up-design.md` (UX & shell, The cross, Hero images, Product → Pro, Milestones item 11).

## Global Constraints

- All earlier plans' global constraints apply (`AGENTS.md`, `.claude/rules/*`): TDD, a fix and its test in separate commits, every user-facing string in **both** `en` and `cs` resw, feature docs in `docs/<topic>.md` plus one index line, no new Uno.Extensions / Uno Toolkit / Uno Themes dependency.
- **Anti-goal (spec):** no Bodi logos, key art, photos or video. Program names are used nominatively only. Hero art and the app icon are original. The "Not affiliated with or endorsed by Bodi / Beachbody" disclaimer (resource `AboutDisclaimer`) appears in the store listing text too.
- **Celebration (spec):** "Small confetti/streak celebration on finishing a week/phase/program." It respects reduced motion (static, no particles), and the sound and haptics toggles (`IMarkingFeedback.SoundEnabled` / `HapticsEnabled`).
- **Pro (spec):** "full stats/streak history" is Pro. Gate with the existing `ProFeature.FullHistory`; do not add an enum value. Free keeps what History gives it today plus the Free statistics named in Task 3.
- **Accountability is never paywalled:** finishing a program and its celebration are Free.
- A collection handed to a control may be an `ObservableCollection<T>` (the trimmed Windows package keeps its vtable since #84), but a list that is replaced wholesale stays `IReadOnlyList<T>`. Never type a one-item list as `IReadOnlyList<T> = [item]` when a control reads it (#68).
- Dates in statistics are **local calendar dates** (`CompletedSession.CompletedOn`, `BonusWorkoutEntity` date), never derived from a UTC timestamp. Weeks start on the current culture's first day of week.
- UI changes are verified in a running app before the task is reported done: Desktop or WASM through the uno-app MCP or Playwright, Windows through `/run-winui-app`. A screenshot per changed page goes into the PR.
- A Release-only failure is a real failure: any task that adds a control bound to a collection re-runs the packaged Windows smoke path locally (`docs/windows-packaging.md`).

## Review Focus

1. **The last session is crossed while an earlier day is still empty** — the program is not complete; no program celebration, no Finish offer. Test in Task 1.
2. **A completion arrives through sync, or a past day is crossed from the day sheet** — a milestone is celebrated only for a cross the user just made through `ICrossingCoordinator`, and only when *that* cross moved the week/phase/program from incomplete to complete. Test in Task 1 and Task 2.
3. **Optional sessions and rest days** — a week whose only uncrossed items are optional sessions or rest days is complete (same rule as `DayStatus.RequiredCount` / `CountsAsRest`). Test in Task 1.
4. **No data, one day of data, a year of data** — statistics show an empty state instead of dividing by zero, a single bar renders, and the heatmap is capped at 26 weeks. Test in Task 3.
5. **A week that straddles a DST change or a year boundary** — a workout crossed at 23:30 local on Sunday counts for that Sunday's week in a Monday-first culture, and for the next week in a Sunday-first culture. Test in Task 3.

### Task 1: Milestones and finishing a program (Core)

**Files:** Core `Tracking/Milestone.cs`, `Tracking/MilestoneDetector.cs`, `Tracking/IActiveEnrollmentService.cs` + `ActiveEnrollmentService.cs` (add `FinishAsync`), `Marking/CrossingCoordinator.cs`, `Marking/ICrossMoment.cs` (`CrossMomentInfo` gains the milestone), `Marking/CrossMomentPolicy.cs`; tests `Tracking/MilestoneDetectorTests.cs`, `Tracking/FinishProgramTests.cs`, `Marking/CrossingCoordinatorTests.cs`.

**Interfaces:**
- `enum MilestoneKind { Week, Phase, Program }`; `sealed record Milestone(MilestoneKind Kind, string PhaseName, int WeekNumber)`.
- `static class MilestoneDetector { static Milestone? Detect(ProgramTrack track, IReadOnlyList<DayStatus> before, IReadOnlyList<DayStatus> after, int crossedDayIndex); static bool IsProgramComplete(IReadOnlyList<DayStatus> days); }` — returns the highest-ranking unit (Program > Phase > Week) that contains `crossedDayIndex`, was incomplete in `before` and is complete in `after`; `null` otherwise. A unit is complete when every day in it has `Progress == Complete` or `CountsAsRest`. Use `ProgramTrack.Locate(int dayIndex)` for the phase and week. A single-phase program never reports `Phase`.
- `IActiveEnrollmentService.Task<bool> FinishAsync(Guid enrollmentId)` — sets `EndedAt = now` and `EndReason = EnrollmentEndReason.Finished` only when `IsProgramComplete`; returns `false` and changes nothing otherwise. Sends the same change notifications as ending a program.
- `CrossMomentInfo` gains `Milestone? Milestone = null` (last parameter, so existing call sites compile).
- `CrossMomentPolicy.ShouldShow(CrossMomentMode mode, bool isToday, Milestone? milestone)`: a `Program` milestone always shows; a `Week` or `Phase` milestone shows unless `mode == Never`; with no milestone the current rule is unchanged.
- **Finishing is offered, never automatic.** Crossing the last required session leaves the enrollment active; the celebration (Task 2) and a Calendar banner offer *Finish program*. Reason: a mis-tapped last cross can still be uncrossed, and a synced device never ends a program on its own.

### Task 3: Statistics (Core)

**Files:** Core `Stats/StatsModels.cs`, `Stats/StatsCalculator.cs`, `Stats/IStatsService.cs`, `Stats/StatsService.cs`, `ViewModels/StatsViewModel.cs`; tests `Stats/StatsCalculatorTests.cs`, `Stats/StatsServiceTests.cs`, `ViewModels/StatsViewModelTests.cs`.

**Interfaces:**
- `sealed record ActivityEntry(DateOnly Date, int Minutes, WorkoutKind Kind, bool IsBonus)` — one per crossed non-rest session (minutes and kind from the catalog workout of the pinned revision) and one per bonus workout (`DurationMinutes ?? 0`; kind from its catalog workout when `WorkoutId` resolves, `WorkoutKind.Mixed` for a free-text one). Sessions of kind `Rest` are never activity.
- `sealed record WeekBucket(DateOnly WeekStart, int Workouts, int Minutes)`; `sealed record KindBucket(WorkoutKind Kind, int Workouts, int Minutes)`; `sealed record HeatDay(DateOnly Date, int Workouts)`; `sealed record ProgramComparison(Guid EnrollmentId, string Name, int CrossedDays, int ScheduledDays, int LongestStreak, double CompletionRate)`.
- `sealed record StatsSummary(int TotalWorkouts, int TotalMinutes, int ActiveDays, IReadOnlyList<WeekBucket> Weeks, IReadOnlyList<KindBucket> ByKind, IReadOnlyList<HeatDay> Heatmap, IReadOnlyList<ProgramComparison> Programs)`.
- `static class StatsCalculator { static StatsSummary Build(IReadOnlyList<ActivityEntry> entries, IReadOnlyList<ProgramComparison> programs, DateOnly today, DayOfWeek firstDayOfWeek, int weeks, int heatmapWeeks); }` — `Weeks` always has exactly `weeks` buckets ending with the current week (zero-filled), `Heatmap` exactly `heatmapWeeks * 7` days ending on the last day of the current week, `ByKind` sorted by minutes descending and omitting empty kinds. `CompletionRate` is `CrossedDays / ScheduledDays` over scheduled non-rest days up to today (or the end date), `0` when there are none.
- `interface IStatsService { Task<StatsSummary> GetAsync(bool fullHistory); }` — `fullHistory: false` reads only the primary enrollment and the last 28 days (so Free never loads what it hides, like History); `true` reads `GetHistoryAsync()` with `GetHistoryCompletionsAsync` per enrollment and all bonus workouts.
- `StatsViewModel`: Free sees totals and 4 week bars for the current program plus a `ProGateHint` row; Pro (`FeatureGate.CanUse(ProFeature.FullHistory, isPro)`) sees 12 week bars, minutes by kind, the 26-week heatmap and the program comparison. Reloads on `TrackingChangedMessage`, `DataChangedMessage` and at midnight via `LiveRefresher`. Every bar and heatmap cell has an automation name ("Week of Nov 16: 5 workouts, 150 minutes"); heatmap intensity is `Workouts` clamped to 0–3 and exposed as a number, never only as a colour.
